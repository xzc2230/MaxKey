# 服务器部署

一台 Ubuntu 服务器，用 Docker Compose 和 Nginx 跑完全部中间件和应用。下面的命令都在这台服务器上执行。业务系统怎么接入见 [业务系统接入.md](业务系统接入.md)。

服务器上的仓库根目录是 `/opt/maxkey/maxkey-deploy/MaxKey`。`docs/deploy` 在这个目录下面。不要把仓库挪到 `/opt/maxkey`。下面的路径都相对这个仓库根目录。

这台机器的弹性公网 IP 是 `54.82.53.135`，登录用户是 `ubuntu`。四个域名的 A 记录指向这个 IP，DNS 代理关闭：

| 域名 | 用途 | 谁来用 |
| --- | --- | --- |
| `sso.tdafadfaww.com` | MaxKey 登录页 `/maxkey/`，OIDC `/sign/` | 客服、内部运营 |
| `iam-admin.tdafadfaww.com` | 管理端 `/maxkey-mgt/`，接口 `/maxkey-mgt-api/` | 运维 |
| `chat.tdafadfaww.com` | Chatwoot 收件箱，以及业务页面加载的聊天组件 | 客服收件箱；访客和业务客户的页面 |
| `agent.tdafadfaww.com` | 客服登录入口，以及两种聊天测试页 | 客服；部署时用来验收聊天 |

客户不登录 MaxKey，也不把 `sso` 当作自己的入口。正式客户留在业务系统页面里。

## 这台机器上有什么

- 中间件：MaxKey 的 MySQL、MaxKey 的 Redis、Chatwoot 的 Postgres、Chatwoot 的 Redis
- 应用：MaxKey 认证服务、MaxKey 管理服务、两个前端、Chatwoot Web、Chatwoot Sidekiq、客服入口
- 入口：Nginx。宿主机只发布 80 和 443

`docs/deploy/deploy.sh` 在服务器上安装构建工具、生成 `docs/deploy/.env`、编译两个后端、构建两个前端，然后拉起上面全部容器。

`compose.yaml` 里的 `edge`、`iam_data`、`chat_data` 是这台机器内部的 Docker 网络。3306、5432、6379、9526、9527、8526、8527、3000、3011 都不映射到宿主机。

OpenIM 不在这次部署里。仓库里的 `deployment/docker/` 是上游示例，不作为生产入口。

## 三种聊天身份

聊天都进同一个 Chatwoot 收件箱。

| 身份 | 怎么进 | 收件箱里的联系人 |
| --- | --- | --- |
| 客服 | `http://agent.tdafadfaww.com/`，走 MaxKey 登录 | 客服本人，不是客户 |
| 匿名访客 | 业务页面只加载聊天组件；验收页是 `http://agent.tdafadfaww.com/visitor` | 没有业务客户编号 |
| 已登录的业务客户 | 业务页面加载聊天组件，并设置 `系统名:客户编号`。验收页是 `http://agent.tdafadfaww.com/customer?system=order-system&id=customer-1001&name=张三` | `order-system:customer-1001` 这种标识 |

验收页没有计算 HMAC，只在部署检查时使用。正式业务页面必须由服务端计算 `identifier_hash`。三种身份都验收通过之后，再把网站收件箱的强制 HMAC 打开。打开之后，`/customer` 验收页不能再代替正式接入。

## 部署文件

`docs/deploy/`：

| 文件 | 作用 |
| --- | --- |
| `deploy.sh` | 在服务器上构建镜像并启动全部服务。可重复执行 |
| `compose.yaml` | 服务、网络、数据卷 |
| `.env.example` | 复制成 `.env` 后填写。脚本会在空项上生成密钥。`.env` 不提交 |
| `nginx/saas.conf` | 首次 HTTP 入口，Compose 默认挂载这份 |
| `nginx/saas-tls.conf` | 证书就绪后换上 |
| `nginx/proxy-params.conf` | 反向代理头 |
| `nginx/certs/` | 放置 `fullchain.pem` 和 `privkey.pem`，证书不提交 |
| `mysql/init/` | 首次启动前放入建库脚本。数据卷一旦写过，再改这个目录不会重新导入 |

构建用的是仓库里已有的目录：

| 路径 | 作用 |
| --- | --- |
| `maxkey-webs/maxkey-web-maxkey/` | 认证后端，容器端口 9527，上下文 `/sign` |
| `maxkey-webs/maxkey-web-mgt/` | 管理后端，容器端口 9526，上下文 `/maxkey-mgt-api` |
| `maxkey-web-frontend/maxkey-web-ng/` | 认证前端，容器端口 8527，页面 `/maxkey/`，接口 `/sign/` |
| `maxkey-web-frontend/maxkey-web-mgt-ng/` | 管理前端，容器端口 8526，页面 `/maxkey-mgt/`，接口 `/maxkey-mgt-api/` |
| `local-chat/` | 客服入口镜像。Compose 的构建上下文 |
| `sql/v4.2.0/maxkey.sql` | 复制到 `docs/deploy/mysql/init/` 的建库脚本 |

前端生产配置已经是相对路径。构建时保持这个配置，页面里的接口地址走当前域名。

## 1. 创建机器

Ubuntu Server 24.04 LTS 或同一台已经装好的更新版本，64 位，8 vCPU，32 GB 内存，200 GB gp3，绑定弹性公网 IP `54.82.53.135`。时区 `Asia/Shanghai`。部署脚本会把时区设成上海。

安全组只放这三条，来源都是你自己的公网 IP，写成 `x.x.x.x/32`：

- TCP 22
- TCP 80
- TCP 443

不要添加 3306、5432、6379、9526、9527。

80 和 443 在启动 Nginx 前必须空着。这台机器上如果还有别的程序绑定这两个端口，先停掉那个程序。

## 2. 安装 Docker

```bash
ssh -i 你的密钥.pem ubuntu@54.82.53.135
sudo timedatectl set-timezone Asia/Shanghai
docker compose version
```

`docker compose version` 能打出版本号就不要再装 Docker。已经用 Docker 官方源装过 `docker-ce` 和 `docker-compose-plugin` 时，再执行 `apt install docker.io docker-compose-v2` 会卸掉 Docker CE，并在 `/usr/libexec/docker/cli-plugins/docker-compose` 上冲突，dpkg 停在半安装状态。

还没有 Docker 时再安装 Ubuntu 自带的包：

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
sudo usermod -aG docker ubuntu
```

退出再登录，执行 `docker compose version`，能打出版本号再继续。部署脚本发现当前用户还不能访问 Docker 时，会用 `sudo` 继续。脚本自己也会先检查 Compose；已经可用时不会改动 Docker 的包。

## 3. 使用现有仓库目录

仓库留在 `/opt/maxkey/maxkey-deploy/MaxKey`。部署文件是这个目录下的 `docs/deploy/`。

```bash
sudo chown -R ubuntu:ubuntu /opt/maxkey/maxkey-deploy/MaxKey
test -f /opt/maxkey/maxkey-deploy/MaxKey/docs/deploy/compose.yaml && echo OK
```

还没有这份仓库时，克隆到这个目录：

```bash
sudo mkdir -p /opt/maxkey/maxkey-deploy
sudo chown -R ubuntu:ubuntu /opt/maxkey/maxkey-deploy
git clone https://github.com/xzc2230/MaxKey.git /opt/maxkey/maxkey-deploy/MaxKey
```

拉取包含 `docs/deploy/deploy.sh` 的版本：

```bash
cd /opt/maxkey/maxkey-deploy/MaxKey
git pull --ff-only
test -f docs/deploy/deploy.sh && echo OK
```

Compose 只读取仓库里的 `docs/deploy/.env`。`/opt/maxkey/.env` 不参与启动。那个文件如果只是空模板，删掉：

```bash
if [ -f /opt/maxkey/.env ] && ! grep -E '^(MAXKEY_DATABASE_PASSWORD|MAXKEY_JWT_SECRET)=' /opt/maxkey/.env | grep -qv '=$'; then
  rm -f /opt/maxkey/.env
fi
```

## 4. 确认域名

四条 A 记录都指向 `54.82.53.135`，并关闭 CDN 代理：

```text
sso.tdafadfaww.com
iam-admin.tdafadfaww.com
chat.tdafadfaww.com
agent.tdafadfaww.com
```

在服务器上检查解析结果就是本机公网 IP：

```bash
curl -4 -fsS https://checkip.amazonaws.com
getent ahostsv4 sso.tdafadfaww.com
getent ahostsv4 iam-admin.tdafadfaww.com
getent ahostsv4 chat.tdafadfaww.com
getent ahostsv4 agent.tdafadfaww.com
```

`docs/deploy/nginx/saas.conf` 里的 `server_name` 已经是这四个名字。管理端目前是 `allow all`，因为安全组已经限制到来源 IP。以后把 80 和 443 对公网开放之前，先把管理端改成你的公网 IP，并加上 `deny all`。

域名仍然指向 CDN 时，可以先把容器拉起来。浏览器验收要等四条记录直接指向 `54.82.53.135`。

## 5. 在服务器上部署

这一条命令完成这些事：

1. 安装 JDK 21、Node 24.20.0 和 pnpm 12.6.0
2. 生成 `docs/deploy/.env` 里仍为空的密码和密钥，权限设为 `600`。已有的值保留
3. 把 `sql/v4.2.0/maxkey.sql` 放到 `docs/deploy/mysql/init/`
4. 编译认证后端和管理后端，构建四个 MaxKey 镜像
5. 启动 MySQL、两个 Redis 和 Postgres，执行 Chatwoot 的 `db:chatwoot_prepare`，再启动 Chatwoot Web 和 Sidekiq
6. 创建 Chatwoot 账号、Platform App 和网站收件箱，并把账号编号和两个 Token 写回 `.env`
7. 启动两个后端、两个前端、客服入口和 Nginx

```bash
cd /opt/maxkey/maxkey-deploy/MaxKey
bash docs/deploy/deploy.sh
```

第一次会下载镜像并编译前后端，预留几十分钟。脚本打印 `HMAC_TOKEN` 时，把这一行抄到业务系统的服务端。它不写入 `.env`，也不出现在页面里。这一步先不要打开强制 HMAC。

脚本结束时容器都是 `running`。两个数据库是 `healthy`。认证服务检查返回 HTTP 状态码。

这份建库脚本创建管理员 `admin`，密码是 `maxkey`。登录后立刻改掉。

镜像已经存在时，再次执行会保留镜像并重新启动服务。代码更新后重新构建：

```bash
cd /opt/maxkey/maxkey-deploy/MaxKey
git pull --ff-only
bash docs/deploy/deploy.sh --rebuild
```

MySQL 数据卷一旦创建，再改 `mysql/init/` 不会重新导入。第一次启动时如果忘了放入 `maxkey.sql`，确认里面没有需要保留的数据后，删掉卷再执行脚本：

```bash
cd /opt/maxkey/maxkey-deploy/MaxKey
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml down
docker volume rm maxkey-saas_maxkey_mysql
bash docs/deploy/deploy.sh
```

## 6. 注册 OIDC 客户端并验收

用浏览器打开 `http://iam-admin.tdafadfaww.com/maxkey-mgt/`，用 `admin` / `maxkey` 登录，马上修改密码。

在管理端注册客服入口的 OIDC 客户端：

- 协议：OAuth 2.0
- 授权类型：`authorization_code`
- 回调：`http://agent.tdafadfaww.com/callback`
- 范围：`openid profile email read`
- 机构：`1`，与 `MAXKEY_INST_ID` 相同

客户端 ID 保持 `agent-bridge`，明文密钥与 `docs/deploy/.env` 里的 `MAXKEY_CLIENT_SECRET` 相同。MaxKey 库存的是编码后的密钥，`.env` 里写明文。改完后在服务器上重启客服入口：

```bash
cd /opt/maxkey/maxkey-deploy/MaxKey
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml up -d agent-bridge
```

用两个浏览器验收：

1. `http://sso.tdafadfaww.com/maxkey/` 出现登录页。
2. `http://agent.tdafadfaww.com/` 跳到 MaxKey。客服登录后进入 `http://chat.tdafadfaww.com` 的收件箱。
3. 另一个浏览器打开 `http://agent.tdafadfaww.com/visitor`，右下角发一条消息。收件箱出现这条会话，联系人没有业务编号。
4. 再打开 `http://agent.tdafadfaww.com/customer?system=order-system&id=customer-1001&name=张三`，发一条消息。收件箱里的联系人标识是 `order-system:customer-1001`。
5. 从服务器外面访问 3306、5432、6379、9526、9527，连接失败。

## 7. 正式接入前

业务系统开始接入之前：

1. 在 Chatwoot 把这个网站收件箱的强制 HMAC 打开。之后业务页面必须带服务端计算的 `identifier_hash`。
2. 证书放到 `docs/deploy/nginx/certs/fullchain.pem` 和 `privkey.pem`。
3. `.env` 里三个公开地址和 `MAXKEY_PUBLIC_ISSUER` 改成 `https://`，`CHATWOOT_FORCE_SSL=true`。
4. `compose.yaml` 里 Nginx 挂载的配置从 `saas.conf` 换成 `saas-tls.conf`。
5. OIDC 回调改成 `https://agent.tdafadfaww.com/callback`，并在 MaxKey 里改成同一个地址。
6. 准备把 80、443 开放到运维 IP 以外时，管理端 Nginx 改成你的公网 IP，并加上 `deny all`。
7. 执行 `bash docs/deploy/deploy.sh`。

业务页面加载 `https://chat.tdafadfaww.com/packs/js/sdk.js`，客户标识使用 `系统名:客户编号`。接法见 [业务系统接入.md](业务系统接入.md)。

## 失败时看哪里

```bash
cd /opt/maxkey/maxkey-deploy/MaxKey
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml ps
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml logs --tail 100 maxkey-auth
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml logs --tail 100 chatwoot-rails
```

当前用户如果还不能访问 Docker，在这些命令的 `docker` 前加 `sudo`。

| 现象 | 处理 |
| --- | --- |
| 找不到 `docs/deploy/compose.yaml` | 到 `/opt/maxkey/maxkey-deploy/MaxKey` 执行。按第 3 节确认 |
| 脚本提示部署目录不对 | 不要在 `/opt/maxkey` 另放仓库。部署目录只能是 `/opt/maxkey/maxkey-deploy/MaxKey` |
| `.env` 在 `/opt/maxkey/.env` | 密钥只放在仓库里的 `docs/deploy/.env`，权限 `600` |
| 80 或 443 已被占用 | 停掉占用端口的程序后再执行脚本 |
| `Could not get lock /var/lib/dpkg/lock-frontend` | 系统自动更新占用了安装锁。等它结束后重新执行脚本，不要删锁文件 |
| `docker-compose-v2` 试图覆盖 `docker-compose` | 机器上还有 `docker-compose-plugin`。先 `sudo apt-get remove -y docker-compose-plugin`，再 `sudo apt-get -f install -y`，然后 `sudo apt-get install -y docker.io docker-compose-v2`。Compose 已经可用时不要执行这组命令 |
| `ERR_PNPM_IGNORED_BUILDS` 或 `duplicate mapping key: plyr` | `allowBuilds` 里只保留 `plyr: false`。删掉 pnpm 自动写入的 `plyr: set this to true or false` 后重新执行脚本 |
| 域名解析到 CDN 地址，浏览器返回 521 | 四条 A 记录改为 `54.82.53.135`，关闭代理 |
| 管理端能打开，客服入口不能登录 | 按第 6 节注册 OIDC 客户端，再执行一次脚本 |
| 改了 `mysql/init/` 但库是空的 | 数据卷已经初始化过。确认可以清空后，按第 5 节删除 `maxkey-saas_maxkey_mysql` |
| Chatwoot 日志里 `relation "portals" does not exist` | 数据库还没有表。先停掉 Chatwoot，执行 `docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml run --rm --no-deps -T chatwoot-rails bundle exec rails db:chatwoot_prepare`，再 `up -d chatwoot-rails chatwoot-sidekiq` |
| `Password must contain at least 1 uppercase character` | `CHATWOOT_AGENT_PASSWORD` 只有小写十六进制。重新执行脚本会换成含大写字母和特殊字符的密码 |

## 备份

每天备份 MaxKey 的 MySQL 和 Chatwoot 的 Postgres。Redis 只保存会话和队列。Redis 丢失时，客服重新登录，聊天记录仍以数据库为准。

把 `.env`、Nginx 配置、证书和当前镜像 digest 做加密副本，放到这台服务器之外。

## 不要这样做

- 不要把访客或业务客户注册成 MaxKey 用户
- 不要把数据库端口发布到宿主机
- 不要把 `LOGIN_CAPTCHA` 设成 `false`，这个变量同时决定验证码类型
- 不要在生产关闭 MFA
- 不要在生产使用 `latest` 镜像
- 不要让浏览器把租户编号传给 MaxKey。当前 UserInfo 里的 `institution` 是 MaxKey 机构 ID，`tenant_code` 还没有写入令牌
- 不要把 HMAC 密钥写进前端页面或客服入口的 `.env`
- 不要把密钥写进 `/opt/maxkey/.env` 或仓库根目录的 `.env`。Compose 读取的是 `docs/deploy/.env`
- 不要把 `/opt/maxkey/maxkey-deploy/MaxKey` 里的仓库挪到 `/opt/maxkey`
