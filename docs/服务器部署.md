# 服务器部署

一台 Ubuntu 服务器，用 Docker Compose 和 Nginx 跑完全部中间件和应用。业务系统怎么接入见 [业务系统接入.md](业务系统接入.md)。

服务器上的 `/opt/maxkey` 就是这个 Git 仓库的根目录。下面的路径都相对仓库根目录。

这台机器的弹性公网 IP 是 `54.82.53.135`，登录用户是 `ubuntu`。四个域名都解析到这个 IP：

| 域名 | 用途 | 谁来用 |
| --- | --- | --- |
| `sso.tdafadfaww.com` | MaxKey 登录页 `/maxkey/`，OIDC `/sign/` | 客服、内部运营 |
| `iam-admin.tdafadfaww.com` | 管理端 `/maxkey-mgt/`，接口 `/maxkey-mgt-api/` | 运维 |
| `chat.tdafadfaww.com` | Chatwoot 收件箱，以及业务页面加载的聊天组件 | 客服收件箱；访客和业务客户的页面 |
| `agent.tdafadfaww.com` | 客服登录入口，以及两种聊天测试页 | 客服；部署时用来验收聊天 |

客户不登录 MaxKey，也不把 `sso` 当作自己的入口。正式客户留在业务系统页面里。

## 这台机器上有什么

- 中间件：MaxKey 的 MySQL、MaxKey 的 Redis、Chatwoot 的 Postgres、Chatwoot 的 Redis
- 应用：MaxKey 认证服务、MaxKey 管理服务、两个前端、Chatwoot Web、Chatwoot Sidekiq、客服入口
- 入口：Nginx。宿主机只发布 80 和 443

`compose.yaml` 里的 `edge`、`iam_data`、`chat_data` 是这台机器内部的 Docker 网络。3306、5432、6379、9526、9527、8526、8527、3000、3011 都不映射到宿主机。

OpenIM 不在这次部署里。仓库里的 `deployment/docker/` 是上游示例，不作为生产入口。

## 三种聊天身份

聊天都进同一个 Chatwoot 收件箱。

| 身份 | 怎么进 | 收件箱里的联系人 |
| --- | --- | --- |
| 客服 | `http://agent.tdafadfaww.com/`，走 MaxKey 登录 | 客服本人，不是客户 |
| 匿名访客 | 业务页面只加载聊天组件；验收页是 `http://agent.tdafadfaww.com/visitor` | 没有业务客户编号 |
| 已登录的业务客户 | 业务页面加载聊天组件，并设置 `系统名:客户编号`。验收页是 `http://agent.tdafadfaww.com/customer?system=order-system&id=customer-1001&name=张三` | `order-system:customer-1001` 这种标识 |

验收页没有计算 HMAC，只在部署检查时使用。正式业务页面必须由服务端计算 `identifier_hash`。三种身份都验收通过之后，再把网站收件箱的强制 HMAC 打开。打开之后，`/customer` 验收页不能再代替正式接入。

## 部署文件

`docs/deploy/`：

| 文件 | 作用 |
| --- | --- |
| `compose.yaml` | 服务、网络、数据卷 |
| `.env.example` | 复制成 `.env` 后填写。`.env` 不提交 |
| `nginx/saas.conf` | 首次 HTTP 入口，Compose 默认挂载这份 |
| `nginx/saas-tls.conf` | 证书就绪后换上 |
| `nginx/proxy-params.conf` | 反向代理头 |
| `nginx/certs/` | 放置 `fullchain.pem` 和 `privkey.pem`，证书不提交 |
| `mysql/init/` | 首次启动前放入建库脚本。数据卷一旦写过，再改这个目录不会重新导入 |

构建用的是仓库里已有的目录：

| 路径 | 作用 |
| --- | --- |
| `maxkey-webs/maxkey-web-maxkey/` | 认证后端，容器端口 9527，上下文 `/sign` |
| `maxkey-webs/maxkey-web-mgt/` | 管理后端，容器端口 9526，上下文 `/maxkey-mgt-api` |
| `maxkey-web-frontend/maxkey-web-ng/` | 认证前端，容器端口 8527，页面 `/maxkey/`，接口 `/sign/` |
| `maxkey-web-frontend/maxkey-web-mgt-ng/` | 管理前端，容器端口 8526，页面 `/maxkey-mgt/`，接口 `/maxkey-mgt-api/` |
| `local-chat/` | 客服入口镜像。Compose 的构建上下文 |
| `sql/v4.2.0/maxkey.sql` | 复制到 `docs/deploy/mysql/init/` 的建库脚本 |

前端生产配置已经是相对路径，构建时不要改成带域名的地址。

## 1. 创建机器

Ubuntu Server 24.04 LTS，64 位，8 vCPU，32 GB 内存，200 GB gp3，绑定弹性公网 IP `54.82.53.135`。时区 `Asia/Shanghai`。

安全组只放这三条，来源都是你自己的公网 IP，写成 `x.x.x.x/32`：

- TCP 22
- TCP 80
- TCP 443

不要添加 3306、5432、6379、9526、9527。

## 2. 安装 Docker

```bash
ssh -i 你的密钥.pem ubuntu@54.82.53.135
sudo timedatectl set-timezone Asia/Shanghai
sudo apt update
sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
sudo usermod -aG docker ubuntu
```

退出再登录，执行 `docker compose version`，能打出版本号再继续。

## 3. 把仓库放到 /opt/maxkey

在 Windows 上进入 `D:\workspace\MaxKey\source`。这个目录才是 GitHub 仓库。

```powershell
tar -cf maxkey-deploy.tar --exclude=node_modules --exclude=.gradle --exclude=build --exclude=logs .
scp -i 你的密钥.pem maxkey-deploy.tar ubuntu@54.82.53.135:/tmp/
```

在服务器上：

```bash
sudo mkdir -p /opt/maxkey
sudo tar -xf /tmp/maxkey-deploy.tar -C /opt/maxkey
sudo chown -R ubuntu:ubuntu /opt/maxkey
cd /opt/maxkey
```

## 4. 解析域名

四条 A 记录都指向 `54.82.53.135`：

```text
sso.tdafadfaww.com
iam-admin.tdafadfaww.com
chat.tdafadfaww.com
agent.tdafadfaww.com
```

`docs/deploy/nginx/saas.conf` 里的 `server_name` 已经是这四个名字。管理端目前是 `allow all`，因为安全组已经限制到来源 IP。以后把 80 和 443 对公网开放之前，先把管理端改成你的公网 IP，并加上 `deny all`。

## 5. 填写 .env，并放上建库脚本

```bash
cd /opt/maxkey/docs/deploy
cp .env.example .env
chmod 600 .env
```

`.env.example` 里的公开地址已经是这四个域名的 `http://`。密码每项单独生成，不要复用：

```bash
openssl rand -base64 24
openssl rand -base64 48
```

两个 JWT 密钥各自执行一次：

```bash
openssl rand -base64 64 | tr '+/' '-_' | tr -d '='
```

要填的空项：

- `MAXKEY_DATABASE_ROOT_PASSWORD`、`MAXKEY_DATABASE_PASSWORD`、`MAXKEY_REDIS_PASSWORD`
- `MAXKEY_JWT_SECRET`、`MAXKEY_JWT_REFRESH_SECRET`
- `CHATWOOT_POSTGRES_PASSWORD`、`CHATWOOT_REDIS_PASSWORD`
- `CHATWOOT_SECRET_KEY_BASE`、三组 `CHATWOOT_ACTIVE_RECORD_*`
- `MAXKEY_CLIENT_SECRET`：32 位随机字符。`MAXKEY_CLIENT_ID` 先写成 `agent-bridge`
- `CHATWOOT_AGENT_PASSWORD`：下一步创建 Chatwoot 管理员时使用

`CHATWOOT_ACCOUNT_ID`、`CHATWOOT_PLATFORM_TOKEN`、`CHATWOOT_WEBSITE_TOKEN` 先留空。四个 MaxKey 镜像名保持 `.env.example` 里的 tag。`CHATWOOT_FORCE_SSL` 保持 `false`。

```bash
cp /opt/maxkey/sql/v4.2.0/maxkey.sql /opt/maxkey/docs/deploy/mysql/init/
```

这份脚本创建管理员 `admin`，密码是 `maxkey`。登录后立刻改掉。

## 6. 启动中间件和 Chatwoot

这一步不要启动 Nginx 和 MaxKey，四个业务镜像还没构建。

```bash
cd /opt/maxkey
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml up -d \
  maxkey-mysql maxkey-redis chatwoot-postgres chatwoot-redis chatwoot-rails chatwoot-sidekiq
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml ps
```

六个容器都是 `running`，两个数据库是 `healthy`。Chatwoot 第一次会自己建表。看到监听 3000 后检查：

```bash
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml logs -f chatwoot-rails
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml exec chatwoot-rails \
  curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/api
```

返回 `200` 再继续。

## 7. 构建四个 MaxKey 镜像

```bash
sudo apt install -y openjdk-21-jdk
cd /opt/maxkey
./gradlew :maxkey-webs:maxkey-web-maxkey:bootJar :maxkey-webs:maxkey-web-mgt:bootJar
docker build -t maxkey-auth:4.2.0-d7c9d9af maxkey-webs/maxkey-web-maxkey
docker build -t maxkey-mgt:4.2.0-d7c9d9af maxkey-webs/maxkey-web-mgt
```

前端使用仓库声明的 Node 24 和 pnpm 12.6.0。Dockerfile 会拷贝 `dist/browser`。

```bash
curl -fsSL https://deb.nodesource.com/setup_24.x | sudo -E bash -
sudo apt install -y nodejs
sudo corepack enable
sudo corepack prepare pnpm@12.6.0 --activate

cd /opt/maxkey/maxkey-web-frontend/maxkey-web-ng
pnpm install --frozen-lockfile
pnpm run build:prod
docker build -t maxkey-auth-web:4.2.0-d7c9d9af .

cd /opt/maxkey/maxkey-web-frontend/maxkey-web-mgt-ng
pnpm install --frozen-lockfile
pnpm run build:prod
docker build -t maxkey-mgt-web:4.2.0-d7c9d9af .
```

先启动两个后端，确认数据库连通：

```bash
cd /opt/maxkey
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml up -d maxkey-auth maxkey-mgt
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml exec maxkey-auth \
  curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:9527/sign/
```

日志里出现 Tomcat 监听 9527，并且上面的检查有 HTTP 状态码，再继续。

## 8. 创建 Chatwoot 账号和网站收件箱

把 `.env` 里的 `CHATWOOT_AGENT_PASSWORD` 填进下面的 `AGENT_PASSWORD`。这个命令创建账号、管理员、Platform App 和网站收件箱，并打印要回填的值。

```bash
cd /opt/maxkey
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml exec \
  -e AGENT_PASSWORD='这里换成.env里的CHATWOOT_AGENT_PASSWORD' \
  chatwoot-rails bundle exec rails runner '
password = ENV.fetch("AGENT_PASSWORD")
account = Account.find_by(name: "客服") || Account.create!(name: "客服", locale: "zh_CN")
admin = User.from_email("agent-admin@tdafadfaww.com") || User.new(
  name: "客服管理员",
  display_name: "客服管理员",
  email: "agent-admin@tdafadfaww.com",
  password: password,
  password_confirmation: password
)
admin.skip_confirmation!
admin.save!
AccountUser.find_or_create_by!(account: account, user: admin) { |membership| membership.role = :administrator }
platform_app = PlatformApp.find_by(name: "MaxKey Bridge") || PlatformApp.create!(name: "MaxKey Bridge")
platform_app.platform_app_permissibles.find_or_create_by!(permissible: account)
channel = Channel::WebWidget.find_by(account: account) || Channel::WebWidget.create!(
  account: account,
  website_url: "http://chat.tdafadfaww.com",
  welcome_title: "在线咨询",
  welcome_tagline: "请留下你的问题"
)
channel.inbox || Inbox.create!(account: account, name: "网站咨询", channel: channel)
puts "ACCOUNT_ID=#{account.id}"
puts "WEBSITE_TOKEN=#{channel.website_token}"
puts "HMAC_TOKEN=#{channel.hmac_token}"
puts "PLATFORM_TOKEN=#{platform_app.access_token.token}"
'
```

把输出写回 `.env`：

- `CHATWOOT_ACCOUNT_ID`
- `CHATWOOT_WEBSITE_TOKEN`
- `CHATWOOT_PLATFORM_TOKEN`

`HMAC_TOKEN` 只抄到业务系统的服务端，不写入 `.env`，也不要出现在页面里。这一步先不要打开强制 HMAC。

然后构建并启动客服入口：

```bash
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml up -d agent-bridge
```

## 9. 启动 Nginx，并验收三种身份

```bash
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml up -d
```

用浏览器打开 `http://iam-admin.tdafadfaww.com/maxkey-mgt/`，用 `admin` / `maxkey` 登录，马上修改密码。

在管理端注册客服入口的 OIDC 客户端：

- 协议：OAuth 2.0
- 授权类型：`authorization_code`
- 回调：`http://agent.tdafadfaww.com/callback`
- 范围：`openid profile email read`
- 机构：`1`，与 `MAXKEY_INST_ID` 相同

客户端 ID 保持 `agent-bridge`，明文密钥与 `.env` 里的 `MAXKEY_CLIENT_SECRET` 相同。MaxKey 库存的是编码后的密钥，`.env` 里写明文。改完后执行一次：

```bash
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml up -d agent-bridge
```

用两个浏览器验收：

1. `http://sso.tdafadfaww.com/maxkey/` 出现登录页。
2. `http://agent.tdafadfaww.com/` 跳到 MaxKey。客服登录后进入 `http://chat.tdafadfaww.com` 的收件箱。
3. 另一个浏览器打开 `http://agent.tdafadfaww.com/visitor`，右下角发一条消息。收件箱出现这条会话，联系人没有业务编号。
4. 再打开 `http://agent.tdafadfaww.com/customer?system=order-system&id=customer-1001&name=张三`，发一条消息。收件箱里的联系人标识是 `order-system:customer-1001`。
5. 从服务器外面访问 3306、5432、6379、9526、9527，连接失败。

## 10. 正式接入前

业务系统开始接入之前：

1. 在 Chatwoot 把这个网站收件箱的强制 HMAC 打开。之后业务页面必须带服务端计算的 `identifier_hash`。
2. 证书放到 `docs/deploy/nginx/certs/fullchain.pem` 和 `privkey.pem`。
3. `.env` 里三个公开地址和 `MAXKEY_PUBLIC_ISSUER` 改成 `https://`，`CHATWOOT_FORCE_SSL=true`。
4. `compose.yaml` 里 Nginx 挂载的配置从 `saas.conf` 换成 `saas-tls.conf`。
5. OIDC 回调改成 `https://agent.tdafadfaww.com/callback`，并在 MaxKey 里改成同一个地址。
6. 准备把 80、443 开放到运维 IP 以外时，管理端 Nginx 改成你的公网 IP，并加上 `deny all`。
7. 执行 `docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml up -d`。

业务页面加载 `https://chat.tdafadfaww.com/packs/js/sdk.js`，客户标识使用 `系统名:客户编号`。接法见 [业务系统接入.md](业务系统接入.md)。

## 备份

每天备份 MaxKey 的 MySQL 和 Chatwoot 的 Postgres。Redis 只保存会话和队列。Redis 丢失时，客服重新登录，聊天记录仍以数据库为准。

把 `.env`、Nginx 配置、证书和当前镜像 digest 做加密副本，放到这台服务器之外。

## 不要这样做

- 不要把访客或业务客户注册成 MaxKey 用户
- 不要把数据库端口发布到宿主机
- 不要把 `LOGIN_CAPTCHA` 设成 `false`，这个变量同时决定验证码类型
- 不要在生产关闭 MFA
- 不要在生产使用 `latest` 镜像
- 不要让浏览器把租户编号传给 MaxKey。当前 UserInfo 里的 `institution` 是 MaxKey 机构 ID，`tenant_code` 还没有写入令牌
- 不要把 HMAC 密钥写进前端页面或客服入口的 `.env`
