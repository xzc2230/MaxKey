# 服务器部署

本文件说明如何用 Docker Compose 和 Nginx，把中间件和应用部署在同一台服务器上。业务系统接入方式见 [业务系统接入.md](业务系统接入.md)。

这一台机器上同时运行：

- 中间件：MaxKey 的 MySQL、MaxKey 的 Redis、Chatwoot 的 Postgres、Chatwoot 的 Redis
- 应用：MaxKey 认证服务、MaxKey 管理服务、两个前端、Chatwoot Web、Chatwoot Sidekiq、客服入口
- 入口：Nginx

不另备数据库服务器或缓存服务器。`compose.yaml` 里的 `edge`、`iam_data`、`chat_data` 是这台机器内部的 Docker 网络，用来隔离流量，不表示多台主机。数据卷也落在这台机器的磁盘上。

部署文件在 `docs/deploy/`：

- `compose.yaml`：全部服务、网络和数据卷
- `nginx/saas.conf`：内网 HTTP 入口
- `nginx/saas-tls.conf`：正式 HTTPS 入口
- `.env.example`：需要填写的配置项

## 部署哪些服务

| 对外域名 | 用途 | 谁来用 |
| --- | --- | --- |
| `sso.tdafadfaww.com` | MaxKey 登录页和 OIDC | 客服、内部运营 |
| `iam-admin.tdafadfaww.com` | MaxKey 管理端 | 运维，限制来源 IP |
| `chat.tdafadfaww.com` | Chatwoot 收件箱和聊天组件 | 客服收件箱；业务页面加载组件 |
| `agent.tdafadfaww.com` | 客服入口 | 客服。登录 MaxKey 后进入 Chatwoot |

客户不访问 `sso` 和 `agent`。客户留在业务系统自己的页面里，由业务系统把客户身份交给 Chatwoot。

OpenIM 不在本次部署里。

## 服务器

一台 Ubuntu Server 24.04 LTS，amd64：

- 8 vCPU，32 GB 内存，200 GB 磁盘
- 安装 Docker Engine 和 Docker Compose v2
- 时区 `Asia/Shanghai`，开启时间同步
- 安全组只开放 22、80、443。22 只允许运维 IP

32 GB 是这台机器同时跑 MaxKey、Chatwoot 和上述四个中间件的容量。MySQL、Postgres、两套 Redis 都使用本机数据卷，连接地址使用 Compose 服务名，例如 `maxkey-mysql`、`chatwoot-postgres`。

3306、5432、6379、9526、9527、3010、3011 只在本机 Docker 网络内可达。宿主机只发布 Nginx 的 80 和 443。

## 上线前要准备的镜像

MaxKey 四个业务镜像还需要按提交 `d7c9d9af1202726a1a54cd60c110dd917b9d93a6` 构建后，把仓库地址填进 `.env`。本机现在跑的是 jar 和 Angular 开发服务器，不能原样搬到服务器。

构建时注意：

- 认证前端的接口地址写成 `https://sso.tdafadfaww.com/sign/`
- 管理前端的接口地址写成 `https://iam-admin.tdafadfaww.com/maxkey-mgt-api/`
- 后端镜像使用 JRE 21，启动命令是 `java $JAVA_OPTS -jar app.jar`
- 镜像 tag 使用不可变版本，禁止 `latest`
- Chatwoot 同样填写已经验证过的版本，禁止 `latest`

仓库自带的上游 Compose 不作为生产入口。

## 填写配置

```bash
cd docs/deploy
cp .env.example .env
chmod 600 .env
```

四个访问名已经写成 `tdafadfaww.com` 的子域名，并写在 `nginx/saas.conf` 里。管理端的 `allow 10.0.0.0/8` 改成运维网段。

至少生成这些随机值，每项单独生成，不要复用：

- MaxKey 数据库密码和 root 密码
- MaxKey Redis 密码
- 两个 JWT 密钥。各自取 64 个随机字节，再做 base64url 编码
- OIDC 客户端密钥
- Chatwoot 的数据库密码、Redis 密码、`SECRET_KEY_BASE` 和三组加密密钥

内网先用 HTTP 验证时：

- `SSO_PUBLIC_BASE`、`CHAT_PUBLIC_BASE`、`AGENT_PUBLIC_BASE` 使用 `http://`
- `CHATWOOT_FORCE_SSL=false`
- Nginx 使用 `saas.conf`

证书就绪后：

- 三个公开地址和 `MAXKEY_PUBLIC_ISSUER` 改成 `https://`
- `CHATWOOT_FORCE_SSL=true`
- 把 `compose.yaml` 里 Nginx 挂载的配置从 `saas.conf` 换成 `saas-tls.conf`
- 证书放到 `docs/deploy/nginx/certs/fullchain.pem` 和 `privkey.pem`

MaxKey 首次启动前，把处理过的初始化 SQL 放到 `docs/deploy/mysql/init/`。这份 SQL 只在数据卷为空时执行。生产 SQL 需要更换管理员密码，并去掉不需要的演示账号、演示应用和演示回调。初始化完成后不要再改这个目录指望它重新导入。

## 启动

在仓库根目录执行：

```bash
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml up -d
```

启动顺序由 Compose 控制：先起两个数据库和两个 Redis，再起 MaxKey 与 Chatwoot，最后由 Nginx 对外服务。

## 首次初始化

1. 打开 `https://iam-admin.tdafadfaww.com/maxkey-mgt/`，用初始化 SQL 里的管理员登录，立即修改密码。
2. 在 MaxKey 注册 OIDC 客户端，供客服入口使用。
   - 协议：OAuth 2.0
   - 授权类型：`authorization_code`
   - 回调地址：`https://agent.tdafadfaww.com/callback`，必须与 `AGENT_PUBLIC_BASE/callback` 完全一致
   - 范围：`openid profile email read`
   - 机构：与 `MAXKEY_INST_ID` 相同，默认是 `1`
3. 把客户端 ID 和明文密钥写入 `.env` 的 `MAXKEY_CLIENT_ID`、`MAXKEY_CLIENT_SECRET`。MaxKey 库存的是编码后的密钥，`.env` 里写明文。
4. 在 Chatwoot 创建账号、网站收件箱和 Platform App，允许该 App 管理这个账号。
5. 把账号 ID、Platform Token、网站收件箱的 `website_token`、客服初始密码回填到 `.env`。
6. 执行 `docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml up -d` 让客服入口读到新配置。

网站收件箱在生产环境打开身份 HMAC，并把 HMAC 密钥只保存在业务系统服务端。本地测试为了方便没有强制 HMAC，服务器上要打开。

## 验收

- `https://sso.tdafadfaww.com/maxkey/` 出现登录页
- `https://agent.tdafadfaww.com/` 跳到 MaxKey，客服登录后进入 `https://chat.tdafadfaww.com` 的收件箱
- 用另一个浏览器打开业务系统的客户页面，发出的消息出现在这个收件箱，联系人标识是 `系统名:客户编号`
- 从服务器外面访问 3306、5432、6379、9526、9527 失败
- `https://iam-admin.tdafadfaww.com/` 从非运维网段访问被拒绝

## 备份

每天备份 MaxKey 的 MySQL 和 Chatwoot 的 Postgres。Redis 开启了持久化，但它只保存会话和队列；Redis 丢失时，客服重新登录，聊天记录仍以数据库为准。

同时把 `.env`、Nginx 配置、证书和当前镜像 digest 做加密副本，放到这台服务器之外。

## 新的 AWS 服务器：按这个顺序做

下面是一台空白 EC2 的第一次部署。中间件和应用都装在这台机器上。还没有自己的域名时，用公网 IP 的临时域名完成 HTTP 验证，证书以后再加。

这台服务器的弹性公网 IP 是 `54.82.53.135`。下面的登录用户按 Ubuntu 镜像写成 `ubuntu`。

### 1. 创建机器

在 EC2 新建一台实例：

- 系统：Ubuntu Server 24.04 LTS，64 位
- 规格：8 vCPU，32 GB 内存
- 磁盘：200 GB gp3
- 绑定一个弹性公网 IP

安全组只放这三条：

- TCP 22，来源填你自己的公网 IP，写成 `x.x.x.x/32`
- TCP 80，来源先填你自己的公网 IP
- TCP 443，来源先填你自己的公网 IP

不要添加 3306、5432、6379、9526、9527。

### 2. 登录并安装 Docker

```bash
ssh -i 你的密钥.pem ubuntu@54.82.53.135
sudo timedatectl set-timezone Asia/Shanghai
sudo apt update
sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
sudo usermod -aG docker ubuntu
```

退出 SSH 再登录一次，让 docker 组生效。然后执行 `docker compose version`，能打出版本号再继续。

### 3. 把部署文件拷到服务器

在 Windows 上进入 `D:\workspace\MaxKey\source`，这个目录才是 GitHub 仓库。打包时不要把 `node_modules`、`.gradle`、`build` 打进去。

```powershell
tar -cf maxkey-deploy.tar --exclude=node_modules --exclude=.gradle --exclude=build --exclude=logs .
scp -i 你的密钥.pem maxkey-deploy.tar ubuntu@54.82.53.135:/tmp/
```

在服务器上解包：

```bash
sudo mkdir -p /opt/maxkey
sudo tar -xf /tmp/maxkey-deploy.tar -C /opt/maxkey
sudo chown -R ubuntu:ubuntu /opt/maxkey
cd /opt/maxkey
```

### 4. 把域名解析到这台服务器

在 `tdafadfaww.com` 的 DNS 里增加四条 A 记录，都指向 `54.82.53.135`：

```text
sso.tdafadfaww.com
iam-admin.tdafadfaww.com
chat.tdafadfaww.com
agent.tdafadfaww.com
```

Nginx 里的 `server_name` 已经是这四个名字。管理端这次先改成：

```nginx
allow all;
```

正式上线前再改回你的运维网段。

### 5. 生成配置

```bash
cd /opt/maxkey/docs/deploy
cp .env.example .env
chmod 600 .env
```

编辑 `.env`，公开地址全部用 `http://`，例如：

```text
SSO_HOST=sso.tdafadfaww.com
ADMIN_HOST=iam-admin.tdafadfaww.com
CHAT_HOST=chat.tdafadfaww.com
AGENT_HOST=agent.tdafadfaww.com
SSO_PUBLIC_BASE=http://sso.tdafadfaww.com
CHAT_PUBLIC_BASE=http://chat.tdafadfaww.com
AGENT_PUBLIC_BASE=http://agent.tdafadfaww.com
MAXKEY_PUBLIC_ISSUER=http://sso.tdafadfaww.com/sign
CHATWOOT_FORCE_SSL=false
```

密码用下面的命令逐项生成，每项单独执行一次，填进对应变量：

```bash
openssl rand -base64 24
openssl rand -base64 48
```

JWT 两项使用：

```bash
openssl rand -base64 64 | tr '+/' '-_' | tr -d '='
```

`MAXKEY_CLIENT_ID` 先写成 `agent-bridge`。`MAXKEY_CLIENT_SECRET` 先生成一串 32 位随机字符。Chatwoot 的账号 ID、Platform Token、website token 先留空，等第 8 步回填。

准备 MaxKey 首次建库脚本：

```bash
mkdir -p /opt/maxkey/docs/deploy/mysql/init
cp /opt/maxkey/sql/v4.2.0/maxkey.sql /opt/maxkey/docs/deploy/mysql/init/
```

这份脚本会创建管理员 `admin`，密码是 `maxkey`。这台机器只对你的 IP 开放，登录后立刻在管理端改掉这个密码。

### 6. 先启动四个中间件和 Chatwoot

MaxKey 的四个业务镜像还没构建，这一步不要启动 Nginx 和 MaxKey。

```bash
cd /opt/maxkey
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml up -d \
  maxkey-mysql maxkey-redis chatwoot-postgres chatwoot-redis chatwoot-rails chatwoot-sidekiq
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml ps
```

六个容器都是 `running`，数据库还要显示 `healthy`。Chatwoot 第一次启动会自己建表，可能要几分钟。查看进度：

```bash
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml logs -f chatwoot-rails
```

看到监听 3000 端口后，在服务器上检查：

```bash
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml exec chatwoot-rails \
  curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3000/api
```

返回 `200` 再继续。

### 7. 在这台服务器上构建 MaxKey 后端镜像

```bash
sudo apt install -y openjdk-21-jdk
cd /opt/maxkey
./gradlew :maxkey-webs:maxkey-web-maxkey:bootJar :maxkey-webs:maxkey-web-mgt:bootJar
docker build -t maxkey-auth:4.2.0-d7c9d9af maxkey-webs/maxkey-web-maxkey
docker build -t maxkey-mgt:4.2.0-d7c9d9af maxkey-webs/maxkey-web-mgt
```

把 `.env` 里的后端镜像改成：

```text
MAXKEY_AUTH_IMAGE=maxkey-auth:4.2.0-d7c9d9af
MAXKEY_MGT_IMAGE=maxkey-mgt:4.2.0-d7c9d9af
```

两个前端镜像目前还没有 Dockerfile，登录页和管理页要等前端镜像构建完成后才能通过 Nginx 打开。后端可以先单独启动，确认数据库连接正常：

```bash
cd /opt/maxkey
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml up -d maxkey-auth maxkey-mgt
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml logs -f maxkey-auth
```

日志里出现 Tomcat 在 9527 启动后，在服务器上检查：

```bash
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml exec maxkey-auth \
  curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:9527/sign/
```

### 8. 初始化 Chatwoot，再启动客服入口

进入 Chatwoot 容器创建账号、网站收件箱和 Platform App，记下账号 ID、website token 和 platform token，写回 `.env` 的 `CHATWOOT_ACCOUNT_ID`、`CHATWOOT_WEBSITE_TOKEN`、`CHATWOOT_PLATFORM_TOKEN`、`CHATWOOT_AGENT_PASSWORD`。

然后启动客服入口：

```bash
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml up -d agent-bridge
```

客服入口这时还不能从浏览器打开，因为它要经过 Nginx。Nginx 要等两个前端镜像都有了再启动，否则 `maxkey-auth-web` 和 `maxkey-mgt-web` 会因为镜像不存在而失败。

### 9. 有前端镜像之后才对外开放

`.env` 里的 `MAXKEY_AUTH_WEB_IMAGE` 和 `MAXKEY_MGT_WEB_IMAGE` 填好后：

```bash
docker compose --env-file docs/deploy/.env -f docs/deploy/compose.yaml up -d
```

浏览器依次打开：

- `http://sso.tdafadfaww.com/maxkey/`
- `http://agent.tdafadfaww.com/`
- `http://chat.tdafadfaww.com/`

管理端使用 `admin` / `maxkey` 登录后，马上修改密码。然后按本文「首次初始化」注册 OIDC 客户端，回调地址写成 `http://agent.tdafadfaww.com/callback`。

### 10. 启用 HTTPS

证书放到 `docs/deploy/nginx/certs/` 后，把 `.env` 里的三个公开地址和 `MAXKEY_PUBLIC_ISSUER` 改成 `https://`，`CHATWOOT_FORCE_SSL=true`，Nginx 改挂 `saas-tls.conf`，再执行一次 `docker compose up -d`。

## 不要这样做

- 不要把客户注册成 MaxKey 用户
- 不要开放管理端到公网
- 不要把 `LOGIN_CAPTCHA` 设成 `false`，这个变量同时决定验证码类型
- 不要在生产关闭 MFA
- 不要让浏览器直接把租户编号传给 MaxKey。当前 UserInfo 里的 `institution` 是 MaxKey 机构 ID，`tenant_code` 还没有写入令牌
