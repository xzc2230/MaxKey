# 业务系统接入

客服和客户走两条线。客服登录 MaxKey。客户只登录业务系统，不在 MaxKey 建账号。

服务器上的域名和启动方式见 [服务器部署.md](服务器部署.md)。

## 客服工作台

业务系统如果使用统一客服入口，客服打开：

```text
https://agent.tdafadfaww.com/
```

这个地址会把客服带到 MaxKey 登录，登录成功后进入 Chatwoot 收件箱。客户不能打开这个地址。

业务系统如果要做自己的客服工作台，按 OIDC 授权码模式接入 MaxKey。

| 项目 | 地址 |
| --- | --- |
| 发行者 | `https://sso.tdafadfaww.com/sign` |
| 授权 | `GET /sign/authz/oauth/v20/authorize` |
| 令牌 | `POST /sign/authz/oauth/v20/token` |
| 用户信息 | `GET /sign/api/connect/v10/userinfo` |

接入前在 MaxKey 注册一个客户端。回调地址逐字登记，范围使用 `openid profile email`。客户端密钥只放在业务服务端。

授权请求：

```text
GET https://sso.tdafadfaww.com/sign/authz/oauth/v20/authorize
  ?response_type=code
  &client_id=业务系统的客户端ID
  &redirect_uri=https://业务系统/oauth/callback
  &scope=openid profile email
```

服务端用授权码换令牌：

```text
POST https://sso.tdafadfaww.com/sign/authz/oauth/v20/token
Content-Type: application/x-www-form-urlencoded

grant_type=authorization_code
&code=授权码
&redirect_uri=https://业务系统/oauth/callback
&client_id=业务系统的客户端ID
&client_secret=客户端密钥
```

令牌字段优先读 `access_token`。当前 4.2 运行包在部分序列化路径下会把同一个值放在 `value`，服务端两种字段都要识别。

读取身份：

```text
GET https://sso.tdafadfaww.com/sign/api/connect/v10/userinfo
Authorization: Bearer 访问令牌
Accept: application/json
```

用返回里的这些字段识别客服：

| 字段 | 含义 |
| --- | --- |
| `sub` | 客服在 MaxKey 中的身份。按它绑定业务侧客服，不要用邮箱当主键 |
| `institution` | MaxKey 机构 ID。用服务端配置把它映射成业务租户 |
| `name`、`email` | 显示信息 |

访问令牌是不透明字符串，不能按 JWT 解码。`tenant_code` 目前还没有放进令牌，业务系统不要从浏览器参数里接收租户编号。

## 业务客户进线

客户已经在订单、CRM 或其他业务系统登录。业务页面加载 Chatwoot 网站组件，并用业务系统自己的客户编号标识这个人。

页面示例：

```html
<script>
  window.chatwootSettings = { position: "right", locale: "zh_CN", type: "standard" };
  window.addEventListener("chatwoot:ready", function () {
    window.$chatwoot.setUser("order-system:customer-1001", {
      name: "张三",
      email: "customer-1001@customer.test",
      identifier_hash: "由业务服务端计算的HMAC"
    });
    window.$chatwoot.setCustomAttributes({
      source_system: "order-system",
      customer_id: "customer-1001"
    });
  });
  (function (d, t) {
    var g = d.createElement(t), s = d.getElementsByTagName(t)[0];
    g.src = "https://chat.tdafadfaww.com/packs/js/sdk.js";
    g.async = true;
    s.parentNode.insertBefore(g, s);
    g.onload = function () {
      window.chatwootSDK.run({
        websiteToken: "网站收件箱的website_token",
        baseUrl: "https://chat.tdafadfaww.com"
      });
    };
  })(document, "script");
</script>
```

客户标识使用 `系统名:客户编号`，例如 `order-system:customer-1001`、`crm:customer-2002`。同一个客户每次进入都使用同一个标识，Chatwoot 会归到同一个联系人。不同业务系统使用不同的系统名前缀。

`identifier_hash` 由业务服务端计算，算法是用收件箱的 HMAC 密钥对完整标识做 HMAC-SHA256，输出十六进制。HMAC 密钥不能出现在前端页面、移动安装包或日志里。生产收件箱要开启强制 HMAC，这样浏览器无法伪造另一个客户。

`website_token` 可以出现在页面里，它只表示使用哪一个网站收件箱。

## 业务系统自己的消息界面

业务系统不嵌入聊天窗口、而要在自己的界面里收发消息时，由业务服务端调用 Chatwoot 应用 API：

1. 按 `identifier=系统名:客户编号` 创建或查找联系人。
2. 在约定的收件箱里创建会话。
3. 以客户身份写入消息。客服的回复从同一会话取回。

API 令牌只放在业务服务端。客户浏览器不直接调用 Chatwoot 管理接口。

## 本地对照

本机已经有三个入口，用来区分三种身份：

| 地址 | 身份 |
| --- | --- |
| http://127.0.0.1:3011/ | 客服。走 MaxKey 登录 |
| http://127.0.0.1:3011/visitor | 匿名访客。没有业务客户编号 |
| http://127.0.0.1:3011/customer?system=order-system&id=customer-1001&name=张三 | 模拟另一个业务系统里已经登录的客户 |

客服保持在 Chatwoot 收件箱。客户页面用另一个浏览器打开。更换 `system`、`id`、`name` 就会变成另一个联系人。

本地客户页没有计算 HMAC，只能用于这台开发机。服务器上的业务系统必须由服务端生成 `identifier_hash`。
